# 备份与恢复

入口：`系统设置` → `维护` → `备份管理`。弹窗分三个标签：`导出备份`、`导入备份`、`备份列表`。

> [!WARNING]
> 恢复会先清空现有数据，再写入备份内容。中途失败不会自动还原，而且有一类失败会留下**空的主库**（见「恢复后要确认什么」）。
>
> 恢复前还要过一道版本检查：备份版本和当前 AstrBot 的**前两位**必须相同（`4.29.x` 的备份只能恢复到 `4.29.x`）。已经升级、手里只剩旧备份时会被直接拒绝，见「版本不一致时」。
>
> 恢复前请先停掉 AstrBot，并按「恢复前先留一份退路」拷走数据。

## 怎么恢复

1. 在 `导入备份` 标签选择 `.zip`，点 `上传并检查`。备份要先进入服务器上的备份列表才能恢复；文件很大时也可以直接传到 `data/backups` 目录，再回 `备份列表` 点 `刷新列表`。
2. 检查结果会显示备份版本、当前版本、备份时间和数据表数量。前两位不同时，这里会显示「无法导入」。
3. 确认后点 `确认导入`，过程中不要关页面。
4. 完成后会提示「建议立即重启 AstrBot」，点 `立即重启`。

`备份列表` 里已有的备份，点 `恢复此备份` 可以直接跳到第 2 步。

## 恢复前先留一份退路

1. 在 `导出备份` 标签点 `开始导出`，完成后点 `下载备份`，把 ZIP 存到本机。
2. 能访问数据目录时（例如自建部署），停掉 AstrBot 后再拷这些：

```
data/data_v4.db
data/data_v4.db-wal        # 必须：最近的写入可能只在这里
data/data_v4.db-shm        # 建议一起拷，丢了可由 -wal 重建
data/knowledge_base/
data/cmd_config.json
data/mcp_server.json
data/plugins/  data/plugin_data/  data/config/
data/t2i_templates/  data/webchat/  data/skills/
```

数据库是 WAL 模式，只拷主文件会缺一截。

> 恢复会把这些目录先移到 `<目录>.bak` 再解压新内容。`.bak` 只保留一份，下一次恢复会先删掉它——不要指望靠它反复回退。

## 恢复后要确认什么

导入不会中途停下，但以下几种失败**只写进服务端日志**，返回结果和页面上都看不到：

- 单行数据不符（缺列、类型对不上）：该行被丢弃。
- 备份里有当前版本不认识的表：整表跳过。
- 备份格式低于 1.1：插件、插件数据、`data/config` 目录都不导入。

还有一类相反的情况会失败得更彻底：主键/唯一键冲突、`NOT NULL` 违反这类数据库约束错误发生在整批提交时，会让主库导入整体回滚、任务标记为失败——而清空已经提交，此时主库是空的。这种情况只能靠恢复前那份备份。

所以恢复后请核对：`插件` 页里插件是否都在、模型和平台配置有没有回退、知识库能否正常打开、对话记录条数是否正常。

## 版本不一致时

| 情况 | 界面行为 |
|---|---|
| 前两位相同、第三位不同（`4.29.2` ↔ `4.29.4`） | 显示「版本差异警告」，可以继续 |
| 前两位不同（`4.28.x` ↔ `4.29.x`） | 显示「无法导入」，不能继续 |

两个方向一样：旧备份恢复到新版本被拒绝，新备份恢复到旧版本也被拒绝。

这时有两个办法：

1. **从原实例重新导出**：原实例还启动得了的话，先升级到当前版本，再重新导出一份备份。这是最稳的做法。
2. **先在同版本上恢复，再升级**：装一个与备份前两位相同的 AstrBot，恢复成功后再升级。注意这只降低风险，不保证升级后不缺列——升级不会补全所有新增字段。

## 备份包里有什么

备份不是数据库文件的拷贝：数据是逐行导出成 JSON 再打包的，所以只能恢复包里有的内容。

- 包含：主库全部表（不含 TOTP 受信任设备表）、知识库（元数据、文档、向量索引、媒体）、`cmd_config.json` 与 `mcp_server.json`、附件，以及 7 个目录：`directories/plugins/`、`plugin_data/`、`config/`、`t2i_templates/`、`webchat/`、`temp/`、`skills/`。导入按这 7 个名字精确匹配，缺一个就整目录不导。
- 不包含：工作区文件 `data/workspaces`、TOTP 受信任设备记录。

备份总是全量导出，没有选择性导出。但**「全量」不等于「完整」**：某张表导出失败时会被写成空数组，备份仍然显示成功，恢复时就会把目标实例的同名表清空。备份完成后可以打开包里的 `manifest.json`，核对 `statistics.main_db` 里各表行数。

## 常见失败

- **提示「无效的备份文件」**：ZIP 里没有 `manifest.json`，或分片上传没传完。
- **知识库在备份时不可用**：包里不会有 `databases/kb_metadata.json`，恢复时知识库既不清空也不导入。
- **插件全部不见**：这份备份格式低于 1.1，不含插件目录，只能从原实例重新导出。
