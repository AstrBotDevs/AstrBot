# 图片处理

`build_main_agent` 在 Agent 初始化前处理初始图片，包括普通附件、引用图片及插件 `ProviderRequest` 中的图片，直接调用构建函数也适用。请求 Hook 执行后，流水线只检查新增的图片引用；已有引用复用处理结果，不再次检查文件。

## 大小限制与格式

- 模型图片预处理时，原始图片文件超过 **64 MiB** 则在读取内容和解码像素前跳过；原因与保留的原图路径会保存到历史。另向模型提供临时建议：使用可用的文件读取工具，或请用户重发较小的图片，这段建议不保存到历史。小于等于 64 MiB 的图片正常处理。
- 模型使用的单张图片文件**严格小于 512 KiB**（524,288 字节）。限制针对 Base64 编码前的图片文件，不是整个请求体。
- 在管理面板的**配置文件**页面搜索**输入图片最大边长**，对应 `provider_settings.image_compress_options.max_size`，默认 1280 像素。初始图片保持宽高比，小图不会放大；为满足文件体积限制，必要时会进一步缩小。Hook 新增图片同样按配置限制最长边、处理格式和动图，并应用 64 MiB 输入上限和严格小于 512 KiB 的输出限制。
- 方向正常、像素尺寸及文件体积均合规的 JPEG/PNG 保留原始字节。其余静图修正方向后编码为 JPEG；含透明度的图片输出 PNG，即使需要进一步缩小也保留透明通道。
- GIF、动画 WebP、APNG 等动图均匀选取最多 9 帧，包含首尾动画帧，生成白底 3×3 拼图。不足 9 帧的格子留白，APNG 的独立封面不参与采样。
- 重新编码时移除不必要的元数据；与输出色彩空间兼容、且不影响体积达标的色彩配置保留。

CUA 会话中的用户输入图片也遵守这些限制；截图及其他工具返回的图片继续使用各自的处理逻辑。

## 配置项变化

| 原配置项 | 现在的行为 |
| --- | --- |
| 启用图片压缩（`image_compress_enabled`） | 已移除，当前输入图片始终处理。 |
| 压缩质量（`image_compress_options.quality`） | 已移除，自动控制输出体积。 |
| 最大边长（`image_compress_options.max_size`） | 更名为“输入图片最大边长”，同时遵守严格小于 512 KiB 的文件体积限制。 |

旧配置文件中遗留的启用开关和 JPEG 质量值不再影响图片处理。

## 原图路径与文件清理

旧的内嵌图片路径在处理阶段生成普通的 `Image N` 文本说明，包含原图路径，并标明是否来自引用消息。序号按 Hook 和过滤之后的图片顺序生成：额外图片内容块在前，`image_urls` 在后。请求实体和消息模型不新增附件元数据。引用来源和成功生成描述的图片由对应处理步骤直接传递，不解析提示文本推断状态；Hook 后只更新本次流程自己生成的提示对象，保留插件传入的文本。跳过的图片只保留原因和原图路径，不占图片序号；动图会标明已转换为九宫格。交给图片描述模型处理的图片标为已转文字描述，不占主请求的图片序号。

`image_urls` 及图片内容块直接复用合规的本地 JPEG/PNG 文件，不创建工作副本；需要转换的图片才使用处理后的预览文件。提供给模型、供工具读取文件的附件说明仍然指向**原始图片路径**，不会替换为预览路径。原始文件和事件中的图片组件均不被覆盖。

模型预览文件归当前事件所有，事件完成、失败或取消后清理，不再保留跨请求图片转换缓存。同一请求中重复出现的图片引用复用同一份预览，请求 Hook 前后的准备过程也会去重。

在旧路径中，成功本地化的附件原图，包括引用图片，不随事件结束删除。临时目录中的原图仍受 `temp_dir_max_size` 容量清理约束，不属于永久存储。请求收集失败时，尚未成功接管的源文件仍按事件临时文件清理。

显式关闭持久图片上下文时，旧兼容路径会在预览删除前将模型图片以 Base64 data URI 写入历史，且不自动整理旧历史。默认路径保存图库引用，并在继续旧会话时迁移可恢复图片。无法读取的图片会跳过，不影响其他文字和正常图片；取消、资源耗尽及程序错误不会被当作坏图忽略。

第三方 Agent 后端、绕过主 Agent 构建函数直接调用 provider，以及工具返回的图片，不属于本次输入图片处理范围。

## 持久图库

内置 Agent 将收到的图片和工具产生的图片保存到 AstrBot 数据目录下的 `image_assets/`，会话历史只保存轻量 `image_ref`，不内嵌原图字节。图库默认启用（`provider_settings.image_context_enabled=true`）；显式设为 `false` 才使用旧的内嵌图片路径。

构造模型请求时，系统校验当前会话对图片的权限，把仍在历史中的引用在原消息位置还原为经过预处理的视觉输入。图库不额外生成描述、不用描述替代图片，也不安装图片目录、标注或重看工具。明确不支持视觉的模型会收到无法查看图片的提示，图库不会为此额外调用描述模型。图库路径之外原有的图片描述配置保留自身行为。

这里分离的是本地存储和模型输入，并不把历史图片从视觉上下文中删除。用户后续只发文字时，仍在历史中的图片也可能被发送，占用视觉输入 token 和请求体积。常规上下文压缩移出正文的图片仍保留会话关联，但不会自动重新插入后续请求。本功能不实现服务商 Files API 的文件 ID 或服务端上下文缓存，模型适配器继续使用原有图片传输方式。

图片标签提供当前会话中的 occurrence ID，不暴露磁盘路径。`send_message_to_user` 可以使用当前会话里的图片引用 ID 发送图库原图，这个发送操作本身不调用视觉模型，发送前会再次检查权限。支持的模型适配器在每次 SDK 请求及重试前复核权限；无法执行该检查的适配器不会接收图库图片。

会话分支共享不可变图片资产，但独立维护关联；重生成、编辑、重置和删除会在事务中更新关联。自动回收只处理明确解除最后引用的原图，从未关联的孤儿原图留给显式维护。读取原图时校验受管路径和文件完整性。旧描述字段可作为存储格式兼容数据保留，但图库不生成它们，也不用它们构造模型上下文。

图库不增加总容量或单张原图的字节配额；图片校验保留每帧最多 2000 万像素、每图最多 100 帧。视觉请求不额外限制图片数量或 Base64 合计字节。AstrBot 原有预处理仍跳过超过 64 MiB 的输入，并产生严格小于 512 KiB 的预览。图片不可用或未能保存时，将简短处理事实交给当前人格说明，不会谎称图片已保存。

## 旧会话与备份

升级前先保存完整备份。首次继续旧会话时，系统把可恢复的内嵌图片和 AstrBot 临时目录文件迁入图库，不弹窗、不在启动时全库重写、不调用描述模型。恢复的字节标记为 `legacy_model_input`，可能是旧预览而非原始上传文件；迁移不会下载远程 URL 或读取任意服务器文件。

校验源会话快照后，历史与图片关联一起提交；失败保留旧历史，阻止当前轮覆盖。已经发布但尚未关联的文件遵循显式孤儿清理规则。

在线读取和迁移的正文上限为 **16 MiB UTF-8 JSON 字节**，在正文进入 Python 前检查。超限会话仍可列表查看、改名和删除；打开历史、继续聊天、分支和在线导出会被拒绝，在线完整备份也会明确失败。本分支不包含超限历史的离线迁移工具。

备份与便携会话图片包包含关联的图库文件，普通 JSONL 本身不携带原图。关闭图库不会将引用还原为 Base64；降级到不支持图片引用的版本时，需要恢复迁移前的完整备份。
