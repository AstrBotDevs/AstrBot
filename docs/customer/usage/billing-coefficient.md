# 费用如何计算（含服务系数）

## 两层数字

| 类型 | 含义 | 谁看到 |
| :--- | :--- | :--- |
| **真实模型成本** | AstrBot Token 成本控制按模型单价算出的 USD 成本 | 运营侧成本控制面板 |
| **展示白饭** | 真实成本换算人民币后 × **服务系数**，再按 1 元 = 500g 显示 | 用户中心干饭记录 |

```text
展示白饭(g) ≈ 模型USD成本 × 汇率 × 服务系数 × 500
```

默认服务系数 **2**（用户付双倍真成本，多出的是手续/运维/技术费）。**不以「百万 token = 固定元」瞎估。**

## 系数为什么不固定写死在教程里

- 不同套餐可有不同系数或包月价。
- 热度高、单机客户多时，托管方可能微调系数（应提前公告）。

用户中心 **用量页顶部** 应显示：

- 当前生效系数（如 `1.8×`）
- 生效日期
- 套餐包含额度

## 透明度建议（给最终用户）

你应在服务协议中写清：

1. Token 统计来源（对话与插件调模型）
2. 模型单价参考哪张价目（DeepSeek / OpenAI 等）
3. 服务系数定义及调整提前通知天数
4. 包月与超额的结算周期（自然月 / 订阅周期）

本教程站只解释概念；**法律文本与具体价格放在用户中心 / 协议页。**

## 托管方技术说明（给你自己）

- 服务器上 **真实成本** 用 AstrBot Token 成本控制按模型定价计算（与干饭记录同源单价表）。
- **对客户展示** 在 fish-api 乘 `FISH_USAGE_DISPLAY_MULTIPLIER`（默认 2）并换成白饭克数；不把充值折扣 `TOPUP_CREDIT_RATIO` 叠进用量。
- 按客户过滤：`umo` 前缀 = 该客户的 `umo_prefix` / `adapter_id`。
