# 费用如何计算（含服务系数）

## 两层数字

| 类型 | 含义 | 谁看到 |
| :--- | :--- | :--- |
| **原始 Token** | 模型厂商计费依据的用量 | 用户中心可展示 |
| **展示费用** | 在模型成本基础上加 **服务系数** | 用户中心账单、套餐超额 |

```text
展示费用 ≈ 模型成本 × 服务系数
```

**服务系数** 覆盖例如：服务器、带宽、运维、QQ 接入与存储、备份与监控等，会随托管方成本与用户规模调整，**以用户中心当前公示为准**。

## 系数为什么不固定写死在教程里

- 不同套餐可有不同系数或包月价。
- 热度高、单机客户多时，托管方可能微调系数（应提前公告）。

用户中心 **用量页顶部** 应显示：

- 当前生效系数（如 `1.8×`）
- 生效日期
- 套餐包含额度

## 透明度建议（给最终用户）

你应在服务协议中写清：

1. Token 统计来源（对话与插件调模型）
2. 模型单价参考哪张价目（DeepSeek / OpenAI 等）
3. 服务系数定义及调整提前通知天数
4. 包月与超额的结算周期（自然月 / 订阅周期）

本教程站只解释概念；**法律文本与具体价格放在用户中心 / 协议页。**

## 托管方技术说明（给你自己）

- 服务器上 **真实成本** 用 AstrBot Token 成本控制按模型定价计算。
- **对客户展示** 在用户中心 API 层乘 `markup_coefficient`，不要只改插件定价以免搞乱内部核算。
- 按客户过滤：`umo` 前缀 = 该客户的 `platform_id`（如 `default_1906369614:`）。
