## [4.28.0-beta.1] - [WIP]

### Added

- Automatically record readable UMO names (group and sender names) after the
  waking stage finalizes `is_wake`, including plugin-handler wakes. Discord
  writes `group_id` for inbound group messages; proactive send fallbacks that
  cannot resolve `channel` still guess `GROUP_MESSAGE` and write `group_id`.
  (#9909, fork adaptation)
- Add batch selection and deletion to local Skills in the Dashboard, with
  confirmation and partial-failure feedback. (#9906, fork adaptation)
- Add MiraRouter as a chat-completion Provider source with
  `X-APP-CODE: astrbot`.

### Fixed

- Count Anthropic `cache_creation_input_tokens` in `input_other` for both
  extract and streaming usage. (#9881, fork adaptation)
- Subtract Gemini cached tokens from `prompt_token_count` when filling
  `input_other`, clamped at zero. (#9880, fork adaptation)
- Polish en-US MCP `syncProvider` Dashboard strings. (#9896)
- Split fence languages on `:` and expand T2I Shiki languages/aliases.
  (#9892, fork adaptation)
- Cap OneBot, NapCat, Discord, Satori, and Misskey `get_group()` member
  lookup with `GROUP_MEMBER_PAGE_LIMIT` / `GROUP_MEMBER_HARD_CAP`. Over the
  cap, omit `members` and keep a known `member_count`. (#9)

### Documentation

- Document MiraRouter under `/providers` in English and Chinese.

### Fork Adaptations

- UMO auto-name writes use `execution_context.database` and
  `background_tasks`. Automatic upserts never overwrite `user_alias`.
- Skills batch delete stays on the composition `SkillsSection`; zh-CN and
  en-US only.
- MiraRouter registers through `provider_modules.py` and inherits
  `ProviderOpenAIChatCompletions`.
- Keep the existing TypeScript Shiki lazy bundle; do not restore the
  upstream `.js` bundle or a `langs` prop on `ThemeAwareMarkdownCodeBlock`.
- Reuse `group_member_lookup_over_cap`. Satori and Misskey do not write a
  partial enumeration as `member_count` when they have no independent total.
  OneBot and NapCat skip `get_group_member_list` when a known count is already
  over the cap, and do not construct `MessageMember` objects when a fetched
  list is over cap. Discord over-cap still fills `group_admins` from the
  complete cache without publishing `members` or scanning visible-channel
  permissions. Misskey over-cap mutates the inbound copy so fallback
  `group_avatar` and `member_count` are kept; a complete enumeration that
  exceeds the cap after injecting the room owner omits `members` and keeps
  the known total. The complete Misskey path also keeps inbound
  `group_avatar`.

### Fork Deviations

- Upstream release wording and upstream-only artifact links are not copied
  verbatim; this changelog describes the features present in the fork.

## 中文

### 新增

- 唤醒阶段确定 `is_wake` 后自动记录 UMO 可读名称（群名、发送者名），包括插件
  handler 唤醒。Discord 入站群消息才写 `group_id`；取不到 `channel` 的主动发送
  兜底仍会猜 `GROUP_MESSAGE` 并写 `group_id`。 (#9909，fork 适配)
- Dashboard 本地 Skills 支持批量选择与删除，含确认和部分失败反馈。
  (#9906，fork 适配)
- 新增 MiraRouter 聊天补全 Provider 来源，请求带 `X-APP-CODE: astrbot`。

### 修复

- Anthropic 将 `cache_creation_input_tokens` 计入 `input_other`（提取与流式）。
  (#9881，fork 适配)
- Gemini 从 `prompt_token_count` 减去缓存 token，结果不小于 0。
  (#9880，fork 适配)
- 润色 en-US MCP `syncProvider` 文案。 (#9896)
- 围栏语言按 `:` 分割，并扩展 T2I Shiki 语言与别名。 (#9892，fork 适配)
- OneBot、NapCat、Discord、Satori、Misskey 的 `get_group()` 成员枚举遵守
  `GROUP_MEMBER_PAGE_LIMIT` / `GROUP_MEMBER_HARD_CAP`；超限省略 `members`，
  保留已知 `member_count`。 (#9)

### Fork 适配

- UMO 自动名写入走 `execution_context.database` 和 `background_tasks`。自动
  upsert 不覆盖 `user_alias`。
- Skills 批量删除落在 composition 版 `SkillsSection`；只改 zh-CN / en-US。
- MiraRouter 注册进 `provider_modules.py`，继承 `ProviderOpenAIChatCompletions`。
- 保留现有 TypeScript Shiki 懒加载包，不还原上游 `.js` 包，也不给
  `ThemeAwareMarkdownCodeBlock` 加 `langs`。
- 复用 `group_member_lookup_over_cap`。Satori 和 Misskey 没有独立总数时，超限
  不把部分枚举写成 `member_count`。OneBot 和 NapCat 在已知 count 超限时跳过
  成员列表请求；已取回的列表超限时不再构造 `MessageMember`。Discord 超限仍从
  完整缓存填充 `group_admins`，不发布 `members`，也不扫描可见频道权限。
  Misskey 超限改入站拷贝，保留回退的 `group_avatar` 和 `member_count`；完整
  枚举在注入房主后超限则省略 `members` 并保留已知总数。完整枚举路径同样保留
  入站 `group_avatar`。
