## [4.27.6] - [WIP]

### Added

- Enrich inbound group metadata across adapters, including name, member
  count, members, and admins. NapCat follows the same OneBot path. LINE
  `get_group` fills name and member count only and does not enumerate
  members. (#9851, fork adaptation)

### Fixed

- Empty non-streaming message chains skip Respond without logging, receipts,
  or after-send hooks. (#9653, fork adaptation)
- Plugin list payloads use `online_version`. Plugins without persisted
  install sources can still update when they match the default market by
  repo or name. (#9887, fork adaptation)
- DingTalk group conversion leaves `group_name` unset when
  `conversation_title` is missing. (#9851, fork adaptation)

### Documentation

- Document Lark `contact:user.base:readonly` so private-message senders can
  show display names. (#9851)
- Document `AstrBotMessage.group`, `member_count`, and that `get_group()`
  may call platform APIs, returns a copy, and may omit incomplete member
  lists. (#9851)

### Maintenance

- Bumped the CodeQL GitHub Action pin to 4.37.9 with an immutable SHA.
  (#9885, fork adaptation)

### Fork Adaptations

- Do not persist implicit plugin install-source records for default-market
  updates.
- Slack inbound conversion still skips `conversations_info`; `get_group`
  enriches later.
- `get_group` copies the inbound `Group` and does not write back to
  `message_obj.group`.
- Slack, Lark, KOOK, and Mattermost member pagination is hard-capped; over
  the cap, `member_count` is kept and `members` is omitted.
- Telegram group avatars use the adapter file base URL plus bot token.

### Fork Deviations

- Did not replay the upstream Dockerfile `COPY` reorder (#9787): this fork
  already copies manifests, installs dependencies, then copies the source tree.
- Did not replay the WeCom receive-loop offload (#9759): `_start_message_task`
  already keeps the command ACK path responsive.
- Did not replay the persona-manager mobile create-folder dropdown gate
  (#9812): the fork toolbar already always shows create folder.
- Did not replay the first-run `astrbot run` password display change (#9879):
  Dashboard setup is already deferred, `migra_webchat_session.py` stays omitted,
  and the fork 404 already points to `make run`.
- Upstream release wording and upstream-only artifact links are not copied
  verbatim; this changelog describes the features present in the fork.

## 中文

### 新增

- 跨适配器补全入站群元数据，包括名称、成员数、成员和管理员。NapCat 走同一条
  OneBot 路径。LINE 的 `get_group` 只补名称和成员数，不枚举成员。
  (#9851，fork 适配)

### 修复

- 空的非流式消息链跳过 Respond，不打日志、不写回执、不触发发送后钩子。
  (#9653，fork 适配)
- 插件列表载荷使用 `online_version`。无持久化安装源的插件，只要在默认市场
  按 `repo` 或名称匹配，仍可更新。 (#9887，fork 适配)
- 钉钉群消息在缺少 `conversation_title` 时不再崩溃，`group_name` 保持为空。
  (#9851，fork 适配)

### 文档

- 补充飞书 `contact:user.base:readonly`，用于读取私聊发送者显示名。 (#9851)
- 补充 `AstrBotMessage.group`、`member_count`，以及 `get_group()` 可能调用
  平台 API、返回拷贝、不完整时省略成员列表的说明。 (#9851)

### 维护

- 将 CodeQL GitHub Action 钉到 4.37.9 的不可变 SHA。 (#9885，fork 适配)

### Fork 适配

- 默认市场更新不持久化隐式安装源记录。
- Slack 入站转换仍不调用 `conversations_info`；`get_group` 再补全。
- `get_group` 拷贝入站 `Group`，不回写入站对象。
- Slack、飞书、KOOK 和 Mattermost 的成员分页有硬上限；超出后保留
  `member_count`，不发布截断成员列表。
- Telegram 群头像使用适配器文件基址加 bot token。

  再复制源码树。

  可响应。
