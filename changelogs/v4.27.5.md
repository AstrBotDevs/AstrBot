## [4.27.5] - [WIP]

### Changed

- **Breaking:** embed Agent Runner configuration in each profile as
  `agent_runner` (`config_version` 3). Dify, Coze, DashScope, and DeerFlow
  settings are inlined on the profile instead of `provider_type=agent_runner`
  records. Third-party runners also store `persona_id`, `max_steps`, and proxy
  settings on the profile. The local agent is assembled from that profile.
  Dashboard moves Agent Runner off the provider dialog. Existing profiles
  migrate on load. (#9821, fork adaptation)
- **Breaking:** replace `wake_prefix` and `group_wake_policy` with
  `command_prefixes` and `llm_access`. Group mention and reply-to-bot are
  explicit. Inbound private LLM fragments can merge in `TurnCoalesceStage`.
  The unused `file_extract` setting is removed.
- **Breaking:** command identity is `command_id` only
  (`{plugin}:{original path}` with spaces as dots). `alter_cmd` is not migrated
  from Python method names or historical short names such as `plugin_ls` or
  `op`. Unmatched `command_configs` rows are deleted. Built-in commands keep
  declared names and aliases unless Dashboard stored `manual_rename`. Former
  invocation names such as `/plugin ls` and `/reset` are not aliases.
  Conflicting public paths use exclusive occupancy and takeover; Dashboard
  exposes those surfaces.
- Split the main SQLite facade into protocol-aligned mixins. `SQLiteDatabase`
  still composes every domain store, but table models, schema initialization,
  and queries now live under `astrbot/core/db/po/`, `schema.py`, and
  `stores/`.
- Make SQLModel tables the only main-database schema source of truth. Startup
  registers the explicit model registry, runs `create_all`, and applies SQLite
  PRAGMAs. It does not probe `PRAGMA table_info` or patch columns and unique
  indexes onto an existing file. Leftover columns stay until the file is
  deleted.
- **Breaking:** rebuild the main database from the current models. Stop the
  process, delete `data/data_v4.db*` under the runtime root, and start again.
  Conversations, long-term memory, authorization bindings, API keys, and other
  main-database rows are not migrated. Knowledge-base files are unchanged.
- Persist authorization bindings and capabilities as one current-state row per
  normalized scope. Revoke or expiry followed by a new grant revives the
  original row; history stays in `AuthAuditLog`.
- Persist non-null scope keys. Global role bindings use `GLOBAL_SCOPE_ID`;
  all-config capabilities use `ANY_CONFIG_SCOPE_ID`. Uniqueness no longer
  depends on SQLite treating multiple `NULL` values as distinct.
- Make `ApiKeyStore` the sole `AuthCapability` writer. Key create/revoke and
  derived capabilities share one transaction; `grant_capability()` delegates
  to `upsert_capability()`.
- Move runtime `Conversation` to `astrbot/core/conversation_models.py` and
  `Personality` to `astrbot/core/persona_runtime/models.py`.
  `astrbot.core.db.po` no longer exports those names. The plugin SDK still
  exports `Personality` from `astrbot.api.provider`.
- Dashboard provider and bot pages now use a viewport-locked workspace instead
  of a card grid. (#9820, #9825, fork adaptation)
- Dashboard configuration uses a profile menu, collapsible search, a dedicated
  AI panel, and a shared provider selection menu. The unsaved-changes banner
  remains. (#9883, fork adaptation)
- Dashboard config fields marked `secret` are masked by default. (#9824, fork
  adaptation)
- Chat composer keeps a single textarea, moves high-risk tools into the plus
  menu, adds scroll-to-bottom, and splits reasoning expand from the sidebar.
- Chat viewport is locked and tool details are capped. Code surfaces use the
  bundled local monospace font.
- Inbound JSON cards render as compact `[Shared Card]` prompts instead of raw
  JSON.
- The default T2I template uses the redesigned layout on the Playwright
  renderer. (#9803, fork adaptation)
- Remove Dashboard one-click Core updates, GitHub release checks, and the
  desktop-app updater. Restart and pip install stay. Upgrade from a source
  checkout.
- Dashboard statistics, conversations, logs, and traces share a tabbed
  workspace at `/dashboard`. The runtime `data/` file manager stays at `/data`.
  Conversations can be filtered by keyword, UMO, bot, and type, grouped by
  session, and opened from session token rankings. (#9846, #9847, fork
  adaptation)
- **Breaking:** remove the legacy Dashboard SPA paths and redirects
  (`/dashboard/default`, `/conversation`, `/console`, `/trace`, `/normal`, and
  `/system`). Logs now use the `features/logs` catalog.
- Remove Live Chat and Live Voice. Chat uses `/api/v1/unified-chat/ws` only;
  `/api/v1/live-chat/ws` is gone.
- Drop the `boxlite` and `shipyard_fs` Computer Use booters. `shipyard_neo`
  and `cua` remain.
- **Breaking:** plugin archives must contain `metadata.yaml`. `metadata.yml`
  is no longer accepted.
- New dashboard password writes store PBKDF2 in `pbkdf2_password` and leave
  `password` empty. Existing MD5 hashes still verify until the next password
  change.
- WebChat sessions are always private (`FriendMessage`).
  `platform_sessions.is_group` is not on the current model.
- Default Compose files no longer set `privileged`.

### 变更

- **破坏性变更：** 将 Agent Runner 配置内嵌到每个配置档的 `agent_runner`
  （`config_version` 3）。Dify、Coze、DashScope 和 DeerFlow 设置写在配置档上，
  不再使用 `provider_type=agent_runner` 记录。第三方 runner 的 `persona_id`、
  `max_steps` 和代理也写在配置档上；本地 Agent 从该配置档组装。Dashboard 把
  Agent Runner 从提供商对话框挪走。已有配置档在加载时迁移。
  (#9821，fork 适配)
- **破坏性变更：** 用 `command_prefixes` 和 `llm_access` 替换 `wake_prefix` 与
  `group_wake_policy`。群聊提及和回复机器人改为显式条件。私聊 LLM 片段可在
  `TurnCoalesceStage` 合并。未使用的 `file_extract` 配置已删除。
- **破坏性变更：** 指令身份只认 `command_id`（`{plugin}:{original path}`，空格
  换成点）。`alter_cmd` 不从 Python 方法名或历史短名（如 `plugin_ls`、`op`）
  迁移。无法认领的 `command_configs` 行会删除。未在 Dashboard 手动重命名的内置
  指令保持当前声明名和别名。`/plugin ls`、`/reset` 等旧调用名不是别名。
  冲突的公开路径使用独占占用和接管；Dashboard 提供对应操作面。
- 将主 SQLite 门面拆成按域协议对齐的 mixin。`SQLiteDatabase` 仍组合全部域存储，
  但表模型、schema 初始化和查询分别位于 `astrbot/core/db/po/`、`schema.py` 和
  `stores/`。
- 以 SQLModel 表作为主库 schema 的唯一真源。启动时显式注册模型、执行 `create_all`
  并设置 SQLite PRAGMA；不探测 `PRAGMA table_info`，也不给已有文件补列或
  部分唯一索引。残留列会留到文件被删除。
- **破坏性变更：** 按当前模型重建主库。停进程后删除 runtime root 下的
  `data/data_v4.db*` 再启动。会话、长期记忆、授权绑定、API Key 等主库记录不会
  从旧文件迁出。知识库文件不受影响。
- 授权绑定和 capability 按规范化作用域只保留一行当前状态；撤销或过期后重新授权
  会恢复原行，历史写入 `AuthAuditLog`。
- 持久化非空 scope key。角色绑定的全局作用域使用 `GLOBAL_SCOPE_ID`；适用于所有
  配置的 capability 使用 `ANY_CONFIG_SCOPE_ID`。唯一性不再依赖 SQLite 把多个
  `NULL` 当作互不相等。
- `ApiKeyStore` 成为 `AuthCapability` 的唯一写入者。创建/撤销 key 与派生
  capability 在同一事务中完成；`grant_capability()` 委托 `upsert_capability()`。
- 将运行时 `Conversation` 移到 `astrbot/core/conversation_models.py`，将
  `Personality` 移到 `astrbot/core/persona_runtime/models.py`。
  `astrbot.core.db.po` 不再导出这两个名字。插件 SDK 仍从 `astrbot.api.provider`
  导出 `Personality`。
- Dashboard 提供商页和机器人页改为视口锁定的工作区，不再使用卡片网格。
  (#9820、#9825，fork 适配)
- Dashboard 配置改为配置档菜单、可折叠搜索、独立 AI 面板和共享提供商选择菜单；
  未保存更改横幅保留。 (#9883，fork 适配)
- 标记 `secret` 的 Dashboard 配置项默认遮罩。 (#9824，fork 适配)
- Chat 输入框保持单个 textarea，高风险工具移入加号菜单，增加滚到底部，并把
  推理展开与侧栏打开分开。
- 锁定聊天视口并限制工具详情。代码区使用内置本地等宽字体。
- 入站 JSON 卡片渲染为简短 `[Shared Card]` 提示，不再塞入原始 JSON。
- 默认文转图模板在 Playwright 渲染器上使用新版式。 (#9803，fork 适配)
- 移除 Dashboard 一键 Core 更新、GitHub Release 检查和桌面应用更新。重启和 pip
  安装保留。请从源码 checkout 升级。
- Dashboard 统计、会话、日志和链路追踪共用 `/dashboard` 的选项卡工作区。运行时
  `data/` 文件管理器仍在 `/data`。会话可按关键词、UMO、机器人和类型筛选，按会话
  分组，并从会话 token 排行打开。 (#9846、#9847，fork 适配)
- **破坏性变更：** 删除旧 Dashboard SPA 路径及其重定向（`/dashboard/default`、`/conversation`、
  `/console`、`/trace`、`/normal`、`/system`）。日志统一使用 `features/logs` 目录。
- 移除 Live Chat 和 Live Voice。对话只走 `/api/v1/unified-chat/ws`，
  `/api/v1/live-chat/ws` 已删除。
- 移除 `boxlite` 和 `shipyard_fs` Computer Use booter；保留 `shipyard_neo`
  和 `cua`。
- **破坏性变更：** 插件压缩包必须包含 `metadata.yaml`，不再接受

- 新写入的 Dashboard 密码只把 PBKDF2 存入 `pbkdf2_password`，并把
  `password` 留空。已有 MD5 哈希仍可用于登录，直到下次改密。
