## [4.27.4] - 2026-08-20

### Added

- Added a Dashboard data-file manager at `/data` for browsing and editing the
  active runtime `data/` directory, with authenticated file operations,
  Monaco-based text editing, ETag conflict detection, binary downloads, and
  bounded filename search.
- Added filesystem authorization actions for read, write, and high-risk manage
  operations, including role checks, step-up verification, and audit records.
- Display each plugin's last update time in marketplace details, formatted for
  the active Dashboard locale. (#9690)
- Refreshed the Dashboard visual system with a responsive navigation shell,
  consistent light, dark, and system appearance controls, and denser shared
  controls across the management views.
- Added a unified reauthentication dialog for high-risk Dashboard operations.
  Password or TOTP confirmation issues a short-lived, one-time proof bound to
  the exact operation.
- Added a ChatUI high-risk-tool control. Dashboard accounts with the required
  instance or global role can reauthenticate to authorize eligible tools for
  one WebChat conversation and configuration profile; the one-time proofs stay
  only in browser memory.
- Logged the effective Windows local runtime shell to simplify environment
  diagnosis. (#9648)
- Added the SSYCloud chat completion provider. (#9659)

### Changed

- Extended the Dashboard OpenAPI contract and generated client with the data-file
  manager endpoints. Sensitive configuration, databases, runtime assets, and
  symlinks keep their protected or read-only policies.
- Dashboard authentication now uses stable account records as the authority for
  account identity and TOTP. The global `dashboard.totp` configuration snapshot
  is no longer a live authentication source.
- Extended the Dashboard step-up flow to platform, provider, and configuration
  mutations, including create, update, delete, enable/disable, quick actions,
  and configuration saves. Cancelled challenges no longer leave optimistic UI
  state behind.

### Fixed

- Stopped preloading the entire preferences table into memory at startup. Reads
  now use a write overlay and fall back to point queries. (#9747, fork
  adaptation)
- Added an LLM metadata fallback catalog endpoint with tighter response
  validation. (#9725)
- Included JSON cards in group-chat context. (#9655)
- Detected audio formats from file contents and converted Telegram audio files
  into Record components. (#9612, #9702)
- Removed the 10-file batch limit for knowledge-base uploads. Uploads now use
  task-specific staging and process files one at a time to avoid retaining a
  whole batch in memory. (#9701, fork adaptation)
- Preserved the Dashboard password across configuration loads when
  `password_change_required` is set, avoiding unexpected password rotation.
  (#9665)
- Separated reasoning metadata from source-backed provider configurations while
  retaining the model metadata catalog. (#9699, fork adaptation)
- Made Trace code-display foreground colors adapt to the active theme. (#9688)
- Kept MCP servers connected when an optional catalog subscription reaches a
  server-side limit. Connection tests now use the initial catalog without
  opening that optional subscription.
- Preserved the authenticated Dashboard account and authentication strength for
  WebChat and Dashboard-authenticated OpenAPI requests, rather than deriving
  authority from a caller-supplied username.
- Fixed step-up retries for bot enable/disable and configuration updates by
  aligning the issued credential with the bot route's canonical resource ID.
- Recognized both `readOnlyHint` and `read_only_hint` MCP annotations when
  selecting read or write tool permissions.
- Bound Dashboard-authenticated WebChat sessions to their owning account across
  HTTP, SSE, and WebSocket chat paths, preventing one account from adopting
  another account's conversation.
- Accepted synced Weixin Kefu messages that omit `open_kfid` instead of failing
  webhook processing.

### Documentation

- Added bilingual Dashboard data-file manager design documentation covering the
  API contract, authorization model, path safety, file categories, and UI
  behavior.
- Added plugin attribution guidance covering acknowledgements, licenses, and
  required copyright notices.
- Updated the bilingual WebUI, configuration, OpenAPI, and MCP guides for the
  account-scoped TOTP, reauthentication, Dashboard identity, and catalog
  subscription behavior.
- Added a bilingual ShengSuanYun provider guide.

### Maintenance

- Migrated statistics handling away from deprecated interfaces. (#9658)
- Updated the CodeQL GitHub Action pin. (#9721)

### Fork Adaptations

- Kept the fork's task tracking, cancellation handling, and temporary-file
  cleanup in the knowledge-base upload flow.
- Preserved the fork's Chinese and English locale set while separating provider
  reasoning metadata, and retained the bundled local monospace font in Trace.
- Applied the preferences OOM fix to the async-only `PreferenceStore` overlay
  instead of restoring deprecated synchronous preference APIs.

### Fork Deviations

- Did not apply the upstream medium-width Chat sidebar change (#9698): the
  fork's existing `hidden-lg-and-up` layout already keeps the sidebar
  accessible at that breakpoint.
- Did not restore the obsolete remote T2I setup documentation (#9720); this
  fork uses local Playwright rendering.
- Misskey visibility handling was already equivalent, so the upstream alias
  migration (#9674) was not replayed.
- Upstream release wording and upstream-only artifact links are not copied
  verbatim; this changelog describes the features present in the fork.

## 中文

### 新增

- Dashboard 新增 `/data` 数据文件管理器，可浏览和编辑当前运行时 `data/` 目录，支持
  登录态文件操作、Monaco 文本编辑、ETag 冲突检测、二进制下载和有界文件名搜索。
- 新增文件系统读取、写入和高风险管理授权动作，覆盖角色检查、二次验证和审计记录。
- 插件市场详情页新增插件最后更新时间，并按当前 Dashboard 语言环境格式化显示。
  (#9690)
- 重构 Dashboard 视觉体系：采用响应式导航框架，统一浅色、深色和跟随系统的外观
  控制，并在各管理页面使用更紧凑一致的通用控件。
- 为高风险 Dashboard 操作新增统一的二次验证弹窗。密码或 TOTP 验证会签发仅限当前
  精确操作使用的短时一次性凭证。
- ChatUI 新增高风险工具控制。拥有所需实例级或全局角色的 Dashboard 账户可重新验证，
  为一个 WebChat 会话和配置文件中的合规工具授权；一次性凭证仅保存在浏览器内存中。
- 记录 Windows 本地运行时实际使用的 Shell，便于排查环境问题。(#9648)
- 新增 SSYCloud 对话补全提供商。(#9659)

### 变更

- 扩展 Dashboard OpenAPI 契约和生成客户端，加入数据文件管理器接口；敏感配置、数据库、
  运行时资源和符号链接继续遵循受保护或只读策略。
- Dashboard 认证现以稳定的账户记录作为账户身份和 TOTP 的权威来源；全局
  `dashboard.totp` 配置快照不再作为实时认证来源。
- Dashboard 二次验证流程现覆盖平台、提供商和配置变更操作，包括创建、更新、删除、
  启用/停用、快捷操作及配置保存；取消验证后不会遗留错误的乐观更新状态。

### 修复

- 启动时不再把整张偏好设置表预加载到内存；读取改为写覆盖层加按键点查。
  （#9747，fork 适配）
- 为 LLM 元数据增加回退目录接口，并收紧响应校验。（#9725）
- 将 JSON 卡片纳入群聊上下文。（#9655）
- 根据文件内容识别音频格式，并将 Telegram 音频文件转换为 Record 组件。
  （#9612, #9702）
- 取消知识库上传每批最多 10 个文件的限制。上传会使用任务专属暂存目录，并逐个
  处理文件，避免将整批文件保留在内存中。（#9701，fork 适配）
- 当 `password_change_required` 已设置时，后续加载配置不再意外轮换 Dashboard
  密码。（#9665）
- 将 reasoning 元数据与基于源的提供商配置分离，同时保留模型元数据目录。
  （#9699，fork 适配）
- Trace 代码展示的前景色现在会适配当前主题。（#9688）
- MCP 服务的可选目录订阅达到服务端上限时，保持已有连接可用。连接测试改为使用初始
  目录，不再打开该可选订阅。
- WebChat 和使用 Dashboard 认证的 OpenAPI 请求现在会保留已认证 Dashboard 账户及
  认证强度，不再根据调用方提交的用户名推导权限。
- 修复机器人启用/停用和配置更新的二次验证重试，使签发的凭证与机器人路由使用的规范
  资源 ID 保持一致。
- 选择 MCP 工具读写权限时同时识别 `readOnlyHint` 和 `read_only_hint` 注解。
- Dashboard 已认证的 WebChat 会话现在会在 HTTP、SSE 和 WebSocket 聊天路径中绑定其
  创建账户，防止一个账户接管另一个账户的会话。
- 微信客服同步消息缺少 `open_kfid` 时不再导致 Webhook 处理失败。
